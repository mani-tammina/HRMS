## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Response(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.

### Layout
Response(children: (Block | Section | Grid | Tabs)[]) — Root container for every assistant message.
Section(title: string, children: (Block)[], subtitle?: string) — Titled card section grouping related blocks.
Grid(children: (Block)[], columns?: number) — Responsive 1- or 2-column layout grid.
Tabs(items: TabItem[]) — Interactive tabbed container.
TabItem(label: string, children: (Block | Section | Grid)[]) — Single tab panel inside Tabs.
Block = any component in Charts, Data, or Content groups. Use Tabs+TabItem for multi-view reports (e.g. Chart + Table) and Grid(children, 2) for side-by-side cards.

### Charts
BarChart(title: string, labels: string[], series: {name: string, values: number[], color?: string}[], subtitle?: string, horizontal?: boolean, stacked?: boolean, yAxisLabel?: string) — Interactive bar chart (vertical/horizontal, grouped/stacked).
LineChart(title: string, labels: string[], series: {name: string, values: number[], color?: string}[], subtitle?: string, smooth?: boolean, filled?: boolean, yAxisLabel?: string) — Interactive line/area trend chart over dates or periods.
PieChart(title: string, slices: {label: string, value: number, color?: string}[], subtitle?: string, donut?: boolean) — Interactive pie or donut chart for proportional splits.
ProgressList(title: string, items: {label: string, value: number, max?: number, displayValue?: string, tone?: "default" | "primary" | "success" | "warning" | "danger"}[], subtitle?: string) — Horizontal progress/share bars for breakdowns, balances, or quotas.
Always use these for charts, comparisons, trends, or breakdowns — never draw ASCII charts in TextBlock.

### Data
DataTable(title: string, columns: string[], rows: (string | number | boolean | any)[][], subtitle?: string, pageSize?: number, exportFileName?: string) — Searchable, sortable, paginated table with built-in CSV/Excel export.
SummaryCard(title: string, subtitle?: string, metrics: {label: string, value: string, tone?: "default" | "primary" | "warning" | "success" | "danger"}[], summary?: string) — KPI metrics card with labeled string values and optional note.
RequestCard(employeeName: string, requestType: string, status: string, submittedDate?: string, dateRange?: string, description?: string, actionHint?: string) — Inbox request detail card (employee, type, status, dates, notes, hint).
KeyValueList(title: string, items: {label: string, value: string, tone?: "default" | "primary" | "success" | "warning" | "danger"}[], subtitle?: string) — Structured 2-column metadata grid (employee profile, record details).
Always use DataTable for multi-row records (timesheets, attendance, leaves, employees) — never pipe-separated text.

### Content & Actions
TextBlock(content: string, tone?: "default" | "info" | "success" | "warning") — Concise prose message or explanation (no tables or ASCII charts).
Callout(title: string, content: string, tone?: "info" | "success" | "warning" | "danger") — Highlighted alert banner with title and body.
GuideSteps(title: string, subtitle?: string, steps: {title: string, detail: string}[], tip?: string) — Numbered step-by-step workflow guide.
ActionButtons(buttons: {label: string, prompt: string, variant?: "primary" | "secondary" | "outline", actionType?: "prompt" | "export_timesheet" | "export_attendance" | "export_leaves" | "open_url", params?: {startDate?: string, endDate?: string, employeeId?: number, url?: string}}[]) — Follow-up buttons or direct downloads via actionType + params.
For real Excel downloads use ActionButtons with actionType: "export_timesheet" and params: { startDate, endDate, employeeId }.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Response(...)` — UI shell appears immediately
2. Component definitions — fill in as they stream
3. Data values — leaf content last

Always write the root = Response(...) statement first so the UI shell appears immediately, even before child data has streamed in.
